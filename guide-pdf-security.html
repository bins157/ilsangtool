1. 서버 업로드 방식 온라인 변환기의 보안 구조와 기밀 유출 리스크

직장인과 학생들은 매일 이미지(JPG·PNG)를 PDF로 묶거나, 여러 개의 PDF 계약서를 하나로 합치거나(병합), 이메일 첨부 용량 제한(보통 10~25MB)을 맞추기 위해 PDF를 압축합니다. 이때 흔히 검색엔진 상단에 나오는 해외 무료 PDF 사이트에 파일을 업로드하곤 합니다.

그러나 전통적인 서버 기반(Server-Side) 온라인 변환기는 사용자의 파일을 외부 클라우드 스토리지에 전송(Upload) → 원격 서버에서 변환 → 다운로드 링크 생성의 과정을 거칩니다. 업체들이 "1시간 후 서버에서 자동 삭제된다"고 안내하더라도, 전송 과정에서 사내 보안 규정(DLP) 위반으로 감지되거나 민감한 개인정보(주민등록번호, 급여 명세, 부동산 계약서)가 외부 서버 디스크를 거친다는 사실 자체가 큰 보안 부담이 됩니다.

2. 100% 브라우저 로컬 연산(Zero-Server Architecture)의 작동 원리

현대 웹 표준 기술의 발전으로 이제 무거운 프로그램(Acrobat 등)을 설치하거나 외부 서버에 파일을 올리지 않고도 사용자의 PC·스마트폰 웹 브라우저 내부 메모리(RAM)에서 직접 문서를 처리할 수 있게 되었습니다.

비교 항목 기존 클라우드 서버 업로드 방식 일상툴 100% 브라우저 로컬 연산 방식
파일 처리 위치 외부 원격 클라우드 서버 사용자 기기(PC·스마트폰) 브라우저 내부 메모리
네트워크 전송량 파일 용량만큼 업로드 + 다운로드 데이터 소모 외부 서버 전송 0 Byte (오프라인 상태에서도 동작)
기밀 문서 보안성 외부 서버 임시 저장으로 사내 보안 정책 저촉 우려 파일이 내 컴퓨터 밖으로 절대 나가지 않아 유출 원천 불가능
처리 속도 및 제한 업로드/다운로드 대기 시간 및 일일 무료 횟수 제한 업로드 대기 없이 1초 만에 즉시 변환 · 무제한 무료

일상툴의 PDF 도구는 모질라(Mozilla) 재단의 오픈소스 렌더링 엔진인 PDF.js와 순수 클라이언트 문서 조작 라이브러리인 pdf-lib, HTML5 Canvas API를 결합하여 모든 페이지 렌더링과 바이트 재조립을 사용자 기기 안에서 완결합니다.

3. PDF 병합·분할·이미지 추출·용량 압축의 실무 활용 매뉴얼

  • 이미지 → PDF 변환: 스마트폰으로 촬영한 영수증, 통장 사본, 신분증 사진 여러 장을 드래그하여 A4 규격(여백 및 세로/가로 방향 지정) 단일 PDF 문서로 즉시 묶어 전자결재 증빙으로 제출할 수 있습니다.
  • PDF 병합(Merge) & 분할(Split): 표지 PDF와 본문 PDF, 첨부 서류 PDF를 원하는 순서대로 합치거나, 100페이지짜리 보고서에서 필요한 3~5페이지만 쏙 뽑아내어 별도 파일로 저장합니다.
  • PDF 용량 압축(Compress): 관공서 전자민원(정부24, 홈택스)이나 이메일 첨부 시 파일 용량이 10MB를 초과할 때, 문서 내 고해상도 비트맵 리소스를 최적 리샘플링하여 화질 저하를 최소화하면서 파일 크기를 50~80% 줄입니다.

4. 무차별 대입 공격(Brute-force)을 무력화하는 비밀번호 엔트로피(Entropy) 공식

계정 해킹의 대다수는 사전 대입 공격(Dictionary Attack)과 무차별 대입 공격(Brute-force Attack)으로 발생합니다. 비밀번호의 수학적 안전도를 나타내는 지표는 정보 엔트로피(Information Entropy, 단위: bit)입니다.

🔐 비밀번호 엔트로피(보안 강도) 계산 공식
E = L × log₂(R)
(E: 엔트로피 비트 수, L: 비밀번호 글자 길이, R: 사용된 문자 집합의 크기)
• 숫자만 사용 시 R = 10 | 영문 소문자만 R = 26 | 대소문자+숫자+특수문자 조합 시 R ≈ 94

예를 들어 숫자만 사용한 6자리 비밀번호(L=6, R=10)의 경우의 수는 백만 개(약 19.9 bit)에 불과해 최신 GPU 연산기로 0.001초 만에 해독됩니다. 반면 영문 대문자(26) + 소문자(26) + 숫자(10) + 특수문자(32)를 섞은 16자리 랜덤 비밀번호(L=16, R=94)는 약 104.8 bit의 엔트로피를 가지며, 슈퍼컴퓨터로도 수조 년이 걸려 사실상 해독이 불가능합니다.

5. Math.random()과 Web Crypto API(CSPRNG) 암호학적 난수의 결정적 차이

일반적인 프로그래밍의 Math.random() 함수는 시드(Seed) 값에 의해 다음 숫자를 예측할 수 있는 의사난수(PRNG)이므로 보안 패스워드 생성에 사용하면 안 됩니다. 일상툴의 비밀번호 생성기는 운영체제 커널의 하드웨어 엔트로피 소스를 직접 참조하는 웹 표준 window.crypto.getRandomValues() (암호학적 안전 의사난수 생성기, CSPRNG)를 사용하여 예측 불가능한 무결점 패스워드를 생성합니다.

Q1. 인터넷 연결(와이파이)을 끊은 상태에서 일상툴 PDF 변환기를 써도 작동하나요?

네! 웹페이지가 한 번 로드된 이후에는 인터넷 랜선을 뽑거나 비행기 모드로 전환한 상태에서 PDF 병합·분할·압축을 실행해도 100% 정상 작동합니다. 이것이 바로 외부 서버로 파일을 전혀 전송하지 않는다는 가장 확실한 증거입니다.

Q2. 안전한 비밀번호는 몇 자리 이상으로 설정하는 것이 권장되나요?

한국인터넷진흥원(KISA) 및 미국 국립표준기술연구소(NIST) 가이드라인에 따르면 영문 대소문자, 숫자, 특수문자를 혼합할 경우 최소 12자리 이상(금융·관리자 계정은 16자리 이상)으로 설정하는 것을 권장합니다.
